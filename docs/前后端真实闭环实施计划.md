# 前后端真实闭环实施计划

## 目标

将项目从“前端 mock + 部分真实 API”推进到可复现的真实闭环：

```text
真实登录 -> JWT 会话恢复 -> AGV 查询/新增/删除 -> Dashboard 展示
-> 告警查询/确认/指派/处理/关闭 -> PostgreSQL 持久化 -> WebSocket 跨窗口同步
```

本阶段范围：Dashboard、Admin、Server、`packages/shared` 和 E2E 测试。传感器真实时序接口、产能报表真实接口暂不纳入闭环验收。

## 方案约定

### 运行模式

- `mock`：认证、业务请求和实时数据全部使用本地 mock，不连接后端 WebSocket。
- `api`：所有业务请求走 Server，失败直接抛错，不允许静默回退 mock。
- `auto`：请求 `/api/health`，只有响应为 JSON 且 `ok === true` 时才解析为 `api`，否则解析为 `mock`。
- Provider 解析后的状态包含 `requestedMode`、`resolvedMode`、`sourceLabel`。
- 联调和简历演示使用 `VITE_API_MODE=api`；离线演示使用 `VITE_API_MODE=mock`。

### 开发连接

两个前端应用均通过 Vite 代理访问后端：

```text
/api -> http://127.0.0.1:8091
/ws  -> ws://127.0.0.1:8091
```

WebSocket 使用 JWT 查询参数连接。未登录或退出登录后不保持连接；重新登录会使用内存中的 token 重建连接。

### 统一业务契约

| 字段     | 约定                                              |
| -------- | ------------------------------------------------- |
| 告警状态 | `active / acknowledged / resolved`                |
| 处理状态 | `unassigned / assigned / in_progress / completed` |
| 指派字段 | `assignedToId`                                    |
| 并发控制 | `version`                                         |
| 关闭字段 | `rootCause / actionTaken / resolution`            |

## 已实施改动

### Shared

- 网络层增加运行时 `api/mock` 模式配置，API 请求失败直接抛错。
- AGV 查询、新增和产能 API 移除真实模式下的静默 mock 回退。
- Provider 的 `auto` 只接受合法健康响应。
- 真实 Dashboard 快照读取真实 AGV 和告警。
- 统一告警实体到共享模型的字段、时间和处理状态映射。
- 增加真实告警统计、处理记录接口和 AGV 删除入口。
- 真实用户补齐权限、邮箱和创建时间字段。
- 登录、恢复会话、退出登录接入实时连接生命周期。
- WebSocket 支持带 JWT 的 URL 和 token 刷新，无 token 时不自动连接。
- `VITE_API_MODE` 参与模式解析：显式 `api`/`mock` 优先，其次环境变量，最后回退 `auto`。
- 会话恢复加去重与守卫等待，刷新页面不再被误判为未登录。
- `withLoading` 同时支持 Promise 与任务函数，并可同步 `submitting` ref。
- 告警关闭与处理记录请求只提交后端 DTO 允许的字段，避免白名单校验 400。

### 前端应用

- Dashboard/Admin Vite 配置增加 `/api`、`/ws` 代理。
- Admin 指派告警时提交当前 `version`。
- Admin 批量删除 AGV 改为调用真实删除 API。
- Playwright 登录路径从历史的 `/account/login` 改为当前实际的 `/login`。

### Server

- 登录响应补充邮箱、权限和创建时间。
- AGV 新增后广播完整 `agv.created` 事件。
- 告警控制器使用 JWT 的 `sub` 作为当前用户 ID。
- 告警处理状态统一为共享枚举。
- 告警确认、指派、处理、关闭均写处理记录并广播完整告警快照。
- 增加 `POST /api/alerts/:id/process` 处理记录接口。

## 本地启动与验收

### 1. 安装与数据库

```powershell
pnpm install
docker compose -f apps/server/docker-compose.yml up -d
```

首次使用空数据库：

```powershell
pnpm --filter @smart/server exec ts-node src/database/sync.ts
pnpm --filter @smart/server seed
```

`sync.ts` 使用 TypeORM schema 同步；`seed` 会清空并重建演示数据，只能用于可丢弃的本地数据库。

### 2. 启动服务

在 Server 终端设置：

```powershell
$env:JWT_SECRET='smart-manufacturing-local-secret'
$env:PG_HOST='127.0.0.1'
$env:PG_PORT='5434'
$env:PG_USER='postgres'
$env:PG_PASSWORD='smart123'
$env:PG_DATABASE='smart_manufacturing'
pnpm --filter @smart/server dev
```

另开终端启动前端：

```powershell
$env:VITE_API_MODE='api'
pnpm --filter smart-dashboard dev
pnpm --filter @smart/admin dev
```

检查：

```text
Dashboard: http://localhost:5173/login
Admin:     http://localhost:5174/login
Health:    http://127.0.0.1:8091/api/health
```

种子库账号：`admin / 123456`。

### 3. 验证命令

本机最终实测通过的完整命令（PostgreSQL 容器映射到 5435）：

```powershell
pnpm --filter @packages/shared build
pnpm --filter @packages/shared exec vitest run
pnpm --filter @smart/server typecheck
pnpm --filter @smart/server test
pnpm --filter smart-dashboard typecheck
pnpm --filter @smart/admin build

$env:VITE_API_MODE='api'
$env:PG_PORT='5435'
pnpm exec playwright test --reporter=list
```

实测结果：

```text
Shared 定向单测     通过（Provider、useFeedback）
Server 集成测试     15/15
Dashboard typecheck 通过
Admin build         通过
Playwright          12/12
```

Playwright 覆盖登录、会话恢复、真实模式断网、AGV 新增跨窗口广播、告警指派与关闭跨窗口同步。

### 4. 告警 E2E 数据说明

告警闭环用例会通过 API 新建一条 `E2E-ALERT-*` 临时告警，在 Admin 界面指派并关闭，再由 Dashboard 断言 `alert.assigned` 与 `alert.closed` 后的状态同步。告警属于审计记录，服务端不提供物理删除接口，因此每次运行会保留一条已解决记录。复跑前无需清理；如需保持演示库整洁，可按 `sensor_id like 'E2E-ALERT-%'` 定向清理。

## 未纳入本次闭环

- 传感器真实时序接口与产能报表真实接口未纳入本轮验收，仍按原计划留在后续任务。
- Admin 历史组件测试中存在旧 mock 假设，全量 Admin 测试结果不作为本次闭环证明；本轮以 Server 集成测试和 Playwright 端到端用例为准。
- Shared 全量单测存在既有失败：feedback 三例为 `vi.mock` 工厂引用提前初始化报错，DataBuffer 两例为快照隔离与性能阈值断言失败；均不在本次闭环改动范围，闭环相关定向单测通过。
- 告警 E2E 产生的已解决审计记录会保留，不做物理删除。
